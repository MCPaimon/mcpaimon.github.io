Change Log — 2.0.0

Permalink for version 2.0.0.

2.0.0 2026-08-03 · One way in

A structural change. Nothing an operator configures is different, but anyone writing an extension against the plugin will need a small edit.

Extension authors need to make two small changes. Calls that used to take a workflow client no longer accept one — drop the argument. The plugin is now obtained through MCAgentsProvider.create(…) rather than constructed directly. Both are mechanical edits, and both are why this is a major version.

Changed A single entry point

  • Storage and the AI workflow are reached through MCAgentsProvider and nothing else.
  • Each server build used to assemble its own database connection, and every AI call carried its own client, so one responsibility lived in several places at once.
  • Choosing a storage backend is unchanged — it is still the database.type setting.

Added The boundary is checked, not just documented

  • A test reads the server-side code and fails the build if anything reaches around that entry point, so the rule holds as the project grows rather than depending on memory.

Added Documented in full

  • Every class, field, and method across the four library pieces carries documentation, and every package explains what it is responsible for.
  • The generated API documentation builds without a single warning, which makes it usable as a reference for extension authors.
