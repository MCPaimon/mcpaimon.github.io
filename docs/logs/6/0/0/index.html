Change Log — 6.0.0

Permalink for version 6.0.0.

6.0.0 Latest 2026-08-05 · MCAgents becomes the core

MCAgents stops being the plugin you talk to and becomes the one everything else is built on. Chatting moves to a plugin of its own, and what stays here is the AI connection, the tools, and the keys.

Breaking. The /ai command no longer exists, and neither does any way to talk to the AI from MCAgents itself. Install MCAgentsChat to keep chatting. The console and tester configuration sections are replaced by a single server key.

Changed Chatting moved out

  • Ask mode, chat mode, conversation memory, running a saved prompt, and the automated test runner are no longer part of this plugin. They live in MCAgentsChat, which reaches this one from outside exactly as any other plugin does.
  • Nothing was dropped in the move. Every feature is still there, behind /chat instead of /ai, and it still uses the tools, the prompts, and the keys kept here.
  • The practical gain is that a server can now run the AI core without in-game chat at all — for NPCs alone, or for a plugin of your own — and a change to how conversation works no longer touches the plugin every other feature depends on.
  • MCAgentsNPC is unaffected and needs no update. It was already built against this plugin's public interface rather than its commands.

Changed The command is now two settings

  • /agents token set <openrouter api key> stores the key your requests spend, replacing /ai token set.
  • /agents model set <openrouter model> chooses the model that answers you, replacing /ai active set. Run it without a model to see what the server offers.
  • Running /agents on its own lists the subcommands you actually hold a permission for.
  • The permission nodes shrink to match: one for the command, one for each setting, both open to players by default.

Added One rule for whose key is spent

  • Every request now says what kind of caller it is for, and that — not who is logged in — decides which API key pays for it.
  • A player spends the key they registered. A guild spends the key stored for the guild. Anything acting for the server spends the new server_openrouter_api_key: the console, an administrative action, and any automated or scheduled work.
  • An operator is still a player. Holding a permission node does not start spending the server's key, so nobody is ever surprised by who paid for a question.
  • A kind of owner the plugin has never heard of works without a change to the rule: store its key the ordinary way and requests made for it resolve to that key. A plugin whose keys live somewhere else entirely can register where to find them instead.
  • A caller with no key is reported as having none, rather than failing somewhere deeper with a provider error.

Changed The configuration follows

  • server_openrouter_api_key replaces the old console and tester sections. It is read from the file on every start, never written to the database, and documented in place with the whole resolution rule.
  • Leaving it unset is allowed. Only requests that actually run as the server fail, and players keep working on their own keys; the plugin warns once at startup.
  • ai_response_timeout moves to MCAgentsChat, which owns the conversation it was guarding.
  • Everything else is unchanged: the models list, the key encryption secret, the tool workflow limit, and every storage backend behave exactly as they did in 5.1.0.

Note Upgrading

  • Install MCAgentsChat if anyone on your server talks to an agent in game. Without it, MCAgents runs perfectly well — there is simply no chat command.
  • Copy your old console.token into server_openrouter_api_key, then delete the console and tester sections. Player keys and models are untouched and need no migration.
  • Tell your players the two renamed commands. Their stored keys still work.
  • A plugin built on MCAgents that passed the console account type must pass the server caller type instead; everything else it calls is unchanged.
  • The downloads are unchanged: the universal MCAgents jar still detects your server at startup, and the three per-server builds are still published alongside it.
