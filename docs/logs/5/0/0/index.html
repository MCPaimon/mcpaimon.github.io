Change Log — 5.0.0

Permalink for version 5.0.0.

5.0.0 2026-08-04 · One provider, real permissions

MCAgents now talks to OpenRouter and nothing else, ships a permission node for every command, and reads the console's credential from the configuration file instead of copying it into the database.

This release changes your configuration and breaks add-ons built for 4.0.0. The platforms list is replaced by openrouter.models, console.platform and tester.platform are gone, the two commands that took a platform name no longer do, and add-ons must be rebuilt against the renamed package. Read the notes below before upgrading, and check for updated PlayerTools and ServerTools releases.

Changed OpenRouter is the only AI platform

  • Every other AI platform integration was removed. OpenRouter's endpoint is built into the plugin, so there is nothing to register and no platform to pick.
  • Models stay yours to choose: OpenRouter serves many of them behind that one endpoint. List the ones your server offers under openrouter.models, and the first entry becomes the server default.
  • A player who has never chosen a model now gets that default instead of an error, so a fresh account works as soon as it has a token.
  • /ai active set takes a model alone, and /ai token set takes a token alone — neither asks for a platform name any more.
  • The agent tool that registered new platforms is gone. The tool that registers a model stays, and now registers it under OpenRouter.
  • Everyone still authenticates with their own OpenRouter key; nothing about the plugin shares one token between players.

Added A permission node for every command

  • Each subcommand now has its own node under the mcpaimon.mcagents. prefix, declared in the plugin so permission managers can see and grant them.
  • Everyday player commands — asking, chatting, saved prompts, choosing a model, storing a token — default to allowed, because a prompt spends the player's own key.
  • The two commands that touch shared state, reloading prompts and running the test suite, default to operators only.
  • Access is no longer decided by operator status alone, so a moderator can be given the test suite, or a guest world can have prompt saving withheld, without touching operator status.
  • The help menu and tab completion list only the subcommands you actually hold a node for, so a withheld command is hidden as well as blocked.

Changed Console and tester credentials come from the config file

  • The console used to be handed a stored account at startup, seeded from the configuration under a fixed placeholder identity. Its key was copied into the database, and later edits to the file changed nothing until that stored copy was overwritten.
  • The console's model and token are now read from the configuration on every prompt, so editing the file and reloading is all it takes and no console key is written to storage.
  • The automated tester works the same way and no longer provisions an account before a run.
  • Player accounts are untouched: the configured credential is never used as a fallback for a player.
  • Because both accounts moved to a derived identity, console and tester history recorded before this release is no longer shown alongside new entries.

Note Add-ons need a rebuild

  • The plugin's classes moved to a base package that names the project rather than only the organization. Add-ons that register tools must update their imports and rebuild.
  • The published artifact coordinates are unchanged, so dependency declarations stay as they were.
  • The plugin's own calls no longer carry a platform identifier, so an add-on that sends prompts or manages tokens through the plugin drops that argument.
  • Everything else — agents, the tool workflow, saved prompts, testing, and every storage backend including the central API server — behaves as it did in 4.0.0.
